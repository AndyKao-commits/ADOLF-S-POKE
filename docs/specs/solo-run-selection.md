# 單人出戰設定：模式、地圖與難度

狀態：工程規格，尚未修改遊戲介面或執行邏輯。依本次討論採用「模式 → 地圖 → 難度」，難度倍率為首輪試調值，待實測。

## 介面配置

桌面版沿用現有主選單：左側原本五款模式按鈕的位置改為「單人出戰設定」，由上而下放三個整列選擇按鈕；中央保留標誌、角色與開始遊戲，右側保留房間功能，下方功能入口維持。手機版把出戰設定置於角色展示下方、開始遊戲上方，各欄一整列。開始按鈕上方顯示「一般・隨機地圖・普通」等即時摘要。

| 欄位 | 首次預設 | 點擊行為 |
|---|---|---|
| 模式 | 一般 | 開啟五款模式宮格 |
| 地圖 | 隨機 | 開啟隨機＋九地區宮格 |
| 難度 | 普通 | 開啟普通、困難、挑戰、惡夢宮格 |

模式「一般」與難度「普通」刻意採不同名稱，避免混淆。既有主畫面地區 select 應由新地圖欄取代，不同時保留兩組控制。

## 選單互動

1. 點選任一欄，開啟置中對話框；同時只允許一個選擇視窗。
2. 模式桌面每列三格、手機每列兩格；地圖桌面每列三格、手機每列兩格；難度固定兩列兩格。
3. 格子包含圖示／地圖縮圖、名稱與簡短說明。選中項目有金框與勾選，不能只依顏色辨識。
4. 點選有效格子立即更新設定、保存、關閉視窗及刷新摘要，不加第二次確認。
5. 關閉按鈕、Esc 或點擊遮罩只關閉，不更改設定；重新開啟時定位至已選項目。
6. 可捲動內容不得超出手機畫面；觸控目標至少 44px。鍵盤可操作，對話框管理焦點，關閉後回到原按鈕。
7. 選擇本身不開始遊戲；玩家按「開始遊戲」才鎖定設定。切換畫面不清空已選設定。

## 模式

沿用 `js/systems/modes.js` 的五個 ID，不另建重複模式：

| ID | 顯示名稱 | 說明 |
|---|---|---|
| normal | 一般 | 原本的敵群、首領與升級流程 |
| shiny | 異色模式 | 敵人為異色寶可夢，原有數量與經驗規則保留 |
| boss | 首領挑戰 | 保留原本首領、起始等級與成長規則 |
| castle | 守護幼犬 | 保留守護目標、波次與勝敗規則 |
| siege | 城堡攻防 | 保留既有攻城規則與單人對手行為 |

五格皆顯示。實際可選狀態應由各模式現有單人支援能力判定，不以 UI 擅自改變玩法；若不可用則顯示原因。模式切換後重新檢查地圖相容性。

## 地圖

選項順序：隨機、關都、城都、豐緣、神奧、合眾、卡洛斯、阿羅拉、伽勒爾、帕底亞。ID 與名稱沿用 `js/world/regions.js`。

- 隨機表示：每局開始時，從目前模式已確認可用的地區中抽一張。選單保持「隨機」，抽到的實際地圖另外寫入本局設定，不能覆蓋下次的隨機偏好。
- 建議以種子均勻抽樣；本局重新載入沿用已鎖定的種子與地圖，不重新抽取。
- 相容清單必須由模式場地邏輯確認，不能假設所有九地區皆適用於守護／攻城專用場景。清單為空或模式使用固定場地時，主欄顯示「模式專用」，保留玩家原地圖偏好供切回一般模式時還原。
- 不相容的地圖格停用並顯示原因，不允許表面選取成功但實際忽略。
- 舊的空字串地區設定代表原場景輪替，並不是新「隨機九地區」。遷移時應明確記錄成 legacy-original；不得把舊存檔地形 ID 直接重編。未有地圖偏好的新玩家預設 random。

## 難度與計算

首次預設普通；僅作用於單人模式。保留多人房間既有的主持人設定與同步流程，單人設定不可覆寫房間難度。

| ID | 名稱 | 敵人生成頻率倍率 | 敵人生命倍率 |
|---|---|---:|---:|
| normal | 普通 | 1.00 | 1.00 |
| hard | 困難 | 1.25 | 1.25 |
| challenge | 挑戰 | 1.50 | 1.50 |
| nightmare | 惡夢 | 2.00 | 2.00 |

以「目前模式、目前進度的現有單人基準」計算，而不是覆蓋成固定怪物數值。現有 `js/net/coop.js` 的單人 autoRate(1)、autoHp(1)、autoXp(1) 均為 1，但這不代表遊戲目前已有四個單人預設。

```text
finalSpawnRate = existingSoloModeSpawnRate × difficulty.spawnRate
finalEnemyHp = existingSoloModeEnemyHp × difficulty.enemyHp
```

倍率只套用一次。不得同時透過多人 count/custom 放大後又套單人倍率。生成倍率調整生成頻率或預算，不把固定首領三隻、守護波次數或勝利條件直接乘倍。新倍率不得突破現有引擎生成／效能上限，若遇上限應在實測報告記錄。

不更改敵人攻擊、速度、每隻敵人經驗、每次掉落機率或獎勵倍率。敵人增加後整局累積經驗與掉落可能增加，這是自然結果，不承諾總獎勵相同。首領與各特殊模式倍率是否需要個別調校須實測，不在首輪另加隱藏係數。

## 設定、保存與開局流程

偏好欄位建議為 `soloRunMode`、`soloMap`、`soloDifficulty`，對應 JSON 所列預設。保留原 runMode、region 的讀取相容層，不能直接讓新設定干擾多人。

```text
進入單人選單 → 讀取並驗證偏好（缺值使用預設）
點選格子 → 驗證可用性 → 更新偏好及摘要 → 保存 → 關閉
開始遊戲 → 再驗證模式／地圖／難度
          → 決定實際地圖與 seed
          → 建立不可變的本局設定快照
          → 用既有模式規則套一次難度倍率 → 開局
```

未知模式或難度回退一般／普通；未知地區回退隨機並提示。專用場地為明確的 mapKind，不以 null 冒充隨機。難度與地圖於開局鎖定，本局途中更改主選單偏好只影響下一局。若無可用地圖或必要場地資源載入失敗，阻止開局並顯示原因，不默默換成另一張。

## 工程位置與驗收

- 介面：`index.html`、`css/style.css`、`js/ui/menu.js`。
- 模式與地圖：`js/systems/modes.js`、`js/world/regions.js`、`js/world/world.js`。
- 難度沿用並隔離檢查：`js/net/coop.js`、實際單人生成與敵人生命計算位置；避免改到多人規則。
- 設定保存、中文名稱與其他語系翻譯同步補齊。

驗收：三欄預設正確；五種模式與十格地圖完整；選後自動關閉、取消不更動；重開記住選擇；隨機偏好不被實際地圖覆蓋；專用場地相容檢查；四難度按基準僅套一次；開始後設定鎖定；舊存檔正常；手機不溢出；多人開局不受影響。

資料表：`docs/specs/solo-run-selection.json`。JSON 的難度為 draft-tuning，地圖相容矩陣需依各模式完成核對後才可接入。此提交只有規格，未部署。
